1. Synthèse

Wilinwi — « Le système d'exploitation du commerce africain » : SaaS multi-tenant de gestion commerciale pour l'Afrique de l'Ouest (POS, stock, trésorerie, CRM, analytics), avec exigences locales : Mobile Money (MTN MoMo, Moov Money), vente à crédit, fonctionnement hors-ligne. Stade actuel : MVP1 « Le Socle » (v0.1.0).

Ce qui ressort le plus de l'analyse :

  • Architecture solide sur l'isolation multi-tenant : RLS PostgreSQL FORCE + withTenant(), double rôle DB, relecture DB à chaque requête.
  • Critique Chaîne lint inopérante (ESLint ni dépendance ni configuré) — la qualité statique ne repose que sur typecheck, et la CI ne le détecte pas.
  • Critique Monétisation neutralisée (gating désactivé, facturation inexistante) alors que le business plan définit 4 plans — angle mort n°1 selon les audits internes.
  • Important Couverture de test très faible (6 fichiers pour ~28 000 LOC), rate-limit du login PIN en mémoire, dérive de migrations en prod documentée dans le README.
  • Build/test non exécutables localement : node_modules absent et installation hors périmètre de la session.

4. Architecture

Monolithe modulaire : 3 applications déployées séparément + 4 packages partagés.

[web :3000] [admin-web :3001] (Vercel) │ REST /api │ ▼ ▼ [API NestJS :4000] ← guards globaux : AuthGuard (JWT Supabase + relecture DB), │ CapabilitiesGuard (RBAC), PlatformAdminGuard, ThrottlerGuard ▼ [@wilinwi/db] withTenant(tenantId) → set_config('app.current_tenant_id') → RLS PostgreSQL │ ▲ │ └── module platform → ADMIN_DATABASE_URL (rôle wilinwi_admin, ▼ fonctions SECURITY DEFINER app.*, contourne RLS volontairement) PostgreSQL/Supabase — schéma multi-tenant (Tenant + tables à tenantId)
  • Points d'entrée : apps/api/src/main.ts (helmet, CORS allowlist, trust proxy, préfixe /api, port 4000) ; apps/api/src/app.module.ts (16 modules + HealthController /health) ; frontends en App Router (src/app/).
  • Modules API : auth, etablissement, stock, inventory, pos (ventes), crm, treasury, analytics, sync, admin, warehouse, notifications, plans, platform, public, common (guards, pipes Zod, PrismaService, AdminPrismaService).
  • Transverse : RBAC dans packages/types/src/roles.ts (matrice unique), masquage DTO par rôle (ex. prixAchat retiré aux vendeurs), idempotence offline via clientGeneratedId.
  • Routes web : dashboard, pos, ventes, stock, clients, tresorerie, entrepot, livraisons, parametres.
